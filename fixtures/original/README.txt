Advisory evidence fixtures v1
Prepared September 30, 2026 for a read-only portfolio demonstration

The vendor-data directory contains two genuine Canonical OpenVEX records, an upstream README and the full CC BY-SA 4.0 license. File content is unchanged and its Git blob identity was checked. Preserve Canonical attribution, original URLs and that data license when redistributing or adapting these files. A future application's code license does not replace the vendor-data license.

The inventory and gold files are original fictional scenarios authored for this demonstration. They do not describe any person's real computer, factory, network or software installation. Their expected decisions are source-reading/identity rules, not independently adjudicated security verdicts. No model, scanner, remediation or live host assessment has been run for this bundle.

The Red Hat/CNA comparison is a small research-authored factual projection with original source links and pointer/blob metadata. It preserves a discrepancy between the inspected vendor HTML and the official CNA record. It is not a signed VEX document or a complete copy of either source. Do not silently resolve it or label a real host safe.

Task boundary: match only exact admitted vendor package identities; distinguish current CVE and historical advisory records; preserve no-match, missing identity, conflicting identity and conflicting source states. A vendor fixed-package statement does not establish that a running service uses that build. A not-affected statement applies only to its declared product and CVE. No results authorize patching, finding suppression, permission changes or ticket closure.

There are 3 development and 6 evaluation cases. Several share package/CVE families, so this is a frozen regression/challenge set, not evidence of unseen-family generalization. Keep gold files evaluator-only. The model may see only the authorized selected source projections, fictional inventory fields and the user's question. Report engineering gates separately from model-answer quality.

See source-manifest.json for exact URLs, source versions, licenses and hashes; contract.json for field/state requirements. This bundle is small static evidence, not a complete vulnerability feed, scanner or enterprise integration.
